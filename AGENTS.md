# AGENTS — работа с репозиторием rpg-retro

Этот файл задаёт ожидания к агенту (и людям) при изменении кода и документации. **Начинать с контекста:** что меняем (баг, фича, док) → читаем релевантные разделы **до** кода.

## Рабочий цикл (кратко)

1. **Scope:** [docs/MVP.md](docs/MVP.md) — **v0.1** (группы, лог) vs **v0.2+** (ретро); не смешивать в одном PR без согласования.  
2. **Продукт vs техника:** [REQUIREMENTS.md](docs/REQUIREMENTS.md) + [CJM.md](docs/CJM.md); [ARCHITECTURE.md](docs/ARCHITECTURE.md) (монорепо `client/` + `server/`) + [adr/](docs/adr/) включая [ADR 0003](docs/adr/0003-client-rendering-phaser.md) (Phaser 3).  
3. **Правка доков:** один первичный источник, остальные — ссылки.  
4. **PR:** DoD — [MVP: Definition of Done (v0.1)](docs/MVP.md#definition-of-done-v01) для волны v0.1; E2E — [E2E.md](docs/E2E.md).

## Правила для агента

1. **Секреты** — никогда не коммитить ключи, пароли, токены. Всё через переменные окружения; в репозитории только `.env.example` с плейсхолдерами.
2. **Согласование scope** — новые крупные фичи, тикеты и изменения границ продукта согласовывать с владельцем проекта. Не раздувать scope «заодно с рефакторингом».
3. **Документация** — при смене архитектурного решения обновлять соответствующий ADR и, при необходимости, `REQUIREMENTS.md` / `ARCHITECTURE.md`. Не дублировать длинные перечисления: один источник правды, остальное — ссылки.
4. **Тикеты (GitLab)** — прямой доступ к GitLab у агента не гарантируется. Тикеты ведутся вручную или через интеграции; при необходимости можно вести зеркало в `docs/BACKLOG.md` **только по согласованию** с владельцем.
5. **Язык** — ответы и комментарии в коде: согласно контексту диалога (русский/английский); имена в коде — на английском, как принято в экосистеме.
6. **Вопросы владельцу** — задавать **в чате (диалог)**, с вариантами **A / B / C** (при необходимости D); **не** оформлять вопросниками в markdown. Итог согласования вносить в [docs/MVP.md](docs/MVP.md) и/или [docs/PROTOCOL.md](docs/PROTOCOL.md) как **факты**, без «вопрос/статус».
