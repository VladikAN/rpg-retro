# Стратегия E2E-тестов

## Цель

Сквозные проверки **критичных путей**; с ростом продукта — дымовые на каждый PR и полные сценарии по [CJM.md](CJM.md).

## Инструмент

- **Playwright** (по умолчанию). Альтернатива: Cypress — зафиксировать в ADR при смене.

## Уровни

| Уровень | Назначение | Когда |
|---------|------------|--------|
| **Дымовые** | Сайт открывается, create/join, health | Каждый PR |
| **v0.1** | Два контекста: создать → ссылка с кодом → **лог** join на арене; неверный код | После [MVP v0.1](MVP.md) |
| **Полный ретро** | Фазы, карточки, голоса | После [MVP v0.2+](MVP.md) |

## Минимальное покрытие (v0.1)

1. **Создатель:** лендинг → **создать** → **ссылка** с path `/g/CODE` или `/join/CODE` ([PROTOCOL](PROTOCOL.md)).  
2. **Гость:** второй контекст → открыть `…/g/CODE` → **имя** в модалке арены → **Phaser** (canvas) и **лог** после join.  
3. **Лог:** видны **два** `player_joined` (или эквивалент).  
4. **Негатив:** несуществующий `CODE` в path — ожидаемая ошибка (после реализации валидации).  

## CI

- Job `e2e`: `docker compose up` (или preview URL), `PLAYWRIGHT_*` из env.  
- Секреты не в коде.
