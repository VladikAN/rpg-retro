# Процесс работы

## Сейчас (старт)

- **Тикеты (issues):** **не** используем. Любое заведение, пересмотр или закрытие — **только с согласованием** владельца проекта.
- **Ветки:** `main` — база; feature-ветки с префиксом, принятым в репо (см. инструкции cloud-агента, если применимы: `cursor/...`).

## После подключения GitLab

*Шаблон — заполнить при миграции:*

- **Один источник правды по задачам:** GitLab Issues (или Jira, если вынесут — зафиксировать здесь).
- **Минимальный flow:** ветка от `main` → MR с описанием → мерж после ревью (самoreview на ранних этапах допустим, если согласовано).
- **CI:** lint + typecheck + unit tests (когда появятся) — **TBD** в `.gitlab-ci.yml`.
- **Релизы:** теги, **docker** образы — `docs/DEPLOYMENT.md`.

## Документация

- **Продукт и дизайн:** `REQUIREMENTS.md`, `GAME_DESIGN.md`.
- **Техника:** `ARCHITECTURE.md`, `DEPLOYMENT.md`, `CODE_STYLE.md`.
- **Агент и память:** `AGENT.md` — сжатый контекст для сессий ИИ-агентов.

*Обновления этих MD — по мере согласованных решений; избегать дублирования длинных кусков между файлами.*

## Вопросы владельцу (с предложениями)

Агент может присылать **уточнения** в формате: вопрос + **свой вариант** по умолчанию, чтобы сократить итерации. Решения затем **вписываются** в соответствующие `docs/*`.
