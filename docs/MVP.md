## Монорепо (фиксированная структура)

Корень репозитория `rpg-retro/` — **один git**, **минимум два проекта**:

| Путь | Стек | Назначение |
|------|------|------------|
| `server/` | **Go** | HTTP, WebSocket, в памяти — комнаты/группы, раздача статики собранного `client/`. |
| `client/` | **TypeScript + Vite + Phaser 3** | Сборка SPA/игры: лендинг, **арена** (сцена Phaser с логом и далее геймплей). |

Корневой `package.json` **опционален** (workspaces) — на усмотрение; обязательны **независимые** `go.mod` (сервер) и `package.json` (клиент).

**Рендер Phaser** — [ADR 0003](adr/0003-client-rendering-phaser.md).

## MVP v0.1 — менеджмент групп + простейший мультиплеер (текущий фокус)

**Задумка владельца:** одна **стартовая страница** с **созданием группы** и **полем ввода** для присоединения к существующей. По **прямой ссылке** с **ключом в path** — сразу **арена**; **имя** вводится **на арене** до WebSocket; Phaser — **lazy** на маршруте арены. Подробно: [PROTOCOL.md](PROTOCOL.md).

**Арена (v0.1)** — отдельный экран/сцена с **логом** событий: например, «игрок подключился», «игрок вышел». Это **не** требует полноты ретро-фаз: цель — **сессии**, **WebSocket** и **синхронное** состояние комнаты.

### Входит в v0.1

- **HTTP:** создать группу (room) → сервер отдаёт **код/ключ** и URL для копирования.  
- **HTTP / маршрутизация:** `GET /g/{CODE}` (и опционально `/join/{CODE}`) отдают SPA; клиент **поднимает арену** и читает код из path ([PROTOCOL](PROTOCOL.md)). После **ввода имени на арене** — **WebSocket** join.  
- **Стартовая страница:** кнопка «создать» + **поле** «подключиться» → `navigate` на `/g/CODE` или `/join/CODE` (тот же экран, что и по прямой ссылке).  
- **WebSocket:** после имени — присоединение к room, **события** join/leave (опционально heartbeat).  
- **Арена в Phaser (lazy):** см. [PROTOCOL.md](PROTOCOL.md); сцена с **логом**; имя **до** WebSocket.  
- **Go** + in-memory **rooms**; **docker-compose** с реальным **server**-образом, статикой фронта.  
- **Health** для CI/ops.

### Вне v0.1 (следующие вехи)

- Все **8 фаз ретро**, карточки, голосования — см. [§ «MVP v0.2+»](#mvp-v02--ядро-ретро-продукт).  
- **Бой**, мобы, движение сущностей.  
- **Передача ведущего**, сложные роли.  
- **Персист** в БД.

### Definition of Done (v0.1)

- [ ] Два браузера: **создать** группу с лендинга, скопировать ссылку с ключом; **второй** открывает ссылку — оба **видят** одну **комнату** (лог: два join).  
- [ ] Уход одного клиента (закрыть вкладку) — **в логе** leave (или тайм-аут) у оставшегося.  
- [ ] `docker compose up` поднимает собранный **client** + **server**.  
- [ ] Нет секретов в репо; **`.env.example`**.

### Эпики (v0.1)

1. **E0** — Монорепо: `server/` (Go), `client/` (Vite+TS+Phaser), общий `Dockerfile` / multi-stage, обновлённый compose.  
2. **E1** — `POST` создать room, `GET` health; модель **room** + **invite code** в памяти.  
3. **E2** — `GET` static: **fallthrough** на `index.html` для `/`, `/g/*`, `/join/*` ([PROTOCOL](PROTOCOL.md)); клиент: **history** router — `/` = лендинг, path = арена + lazy Phaser.  
4. **E3** — WebSocket: join с `inviteCode` (из path) + `displayName` (с формы арены), broadcast `player_joined` / `player_left`.  
5. **E4** — Phaser: сцена **Arena** — лог событий (append строк).  
6. **E5** — E2E smoke: 2 контекста, create → open link → логика join в логе (Playwright).

## MVP v0.2+ — ядро ретро (продукт)

После **v0.1** инкрементально добавляется то, что описано в [REQUIREMENTS.md](REQUIREMENTS.md):

- **Лобби** (по необходимости) и **ведущий**, **8 фаз** ретро (см. [REQUIREMENTS §5](REQUIREMENTS.md) «Этапы ретро»), карточки, **финальное** анонимное голосование, визуал сценария (фон) **без** обязательного боя.  
- Детализация фаз, DoD и эпики **пересобираются** в отдельных тикетах, когда v0.1 **закрыт**; в этом файле **не** дублировать 8 фаз, пока не обновлён план владельцем.

**Связь с прошлым соглашением:** визуальная «картинка» сценария и **все 8** фаз остаются **целевым** поведением продукта, но **следуют** за v0.1, если не пересогласовано иначе.
