# Роли и «навыки» (ориентиры для команды)

Это **не** оргштат, а набор ответственности, которую можно совмещать одним человеком или распределять.

## Тестировщик (QA)

- Поддерживает **E2E** и ручные чек-листы по [CJM.md](CJM.md).
- Следит за **покрытием** критичных сценариев; при изменении CJM — обновляет ожидания тестов.
- Фиксирует дефекты в трекере (GitLab Issues) — когда трекер подключён.

## Разработчик

- Соблюдает архитектурный стиль из [ARCHITECTURE.md](ARCHITECTURE.md) и ADR.
- Принципы: **SOLID**, **DRY**, **KISS** — без догматизма; прагматичный минимум абстракций.
- Не коммитит секреты; конфигурация через env (см. [AGENTS.md](../AGENTS.md)).

## Ревьюер кода

- Проверяет соответствие **тикету** (когда тикеты ведутся) и актуальности **документации** при смене поведения.
- Соединяет взгляд разработчика и требований: «сделано ли то, что описано в REQUIREMENTS/CJM».

## Менеджер / владелец продукта

- Следит за **ходом** разработки и **приоритетами**.
- **Тикеты** — создание, уточнение, закрытие; связь с заказчиком (вами).
- Крупные изменения scope — **согласуются** с владельцем; новые тикеты не плодятся без явного согласия (см. [AGENTS.md](../AGENTS.md)).

## Агент (AI)

- Следует [AGENTS.md](../AGENTS.md); обновляет docs при архитектурных сдвигах; не расширяет scope без согласования.
