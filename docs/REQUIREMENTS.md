# Функциональные требования

Браузерная многопользовательская **шуточная** игра-оболочка для **командных ретро**. **Волны поставки** (v0.1 группы + лог арены, v0.2+ ретро) — [MVP.md](MVP.md). Достаточно устройства с браузером и сетью; коммуникация голосом/чатом — **вне** продукта (Zoom, Discord и т.д.).

> **v0.1** реализует **не** весь перечень ниже сразу, а **менеджмент комнат** и **мультиплеер-лог** на арене; полнота фаз и карточек — **после** закрытия v0.1, если иначе не согласовано.

## 0. Термины (единый смысл для агента и кода)

- **Сессия / комната (room):** логическое пространство с одним ключом приглашения; все участники в ней разделяют одно **серверное** состояние. В коде предпочтительно **room** / `roomID`.
- **Ключ приглашения:** короткий секрет/код для join (не путать с идентификатором сессии в БД, если появится позже).
- **Создатель** — кто **создал** room; **ведущий (facilitator)** — кто **управляет фазами**; могут различаться после передачи роли.
- **Фаза (этап) ретро** — дискретное состояние машины, например `collect_positive`; **переход** фазы — только **ведущий** (если нет тайм-аутов в дальнейшей спеке).
- **Сценарий** — **контент/метафоры** (лор, подписи UI); не путать с **фазами**.
- **Карточка** — пользовательский текст, привязанный к **типу** (положительные/негативные) и **фазе** жизни (сбор / вскрытие и т.д. — детализация в протоколе).
- **Арена** — в **v0.1** (минимум) экран с **событием логом** (join/leave) в [Phaser 3](adr/0003-client-rendering-phaser.md); в полной версии — **игровая** сцена (карта, движение, мобы) + **ретро-UI**; в полном продукте варианты **совмещаются**; детализация — [MVP.md](MVP.md).

## 1. Сессия и приглашение

- Пользователь открывает веб-приложение.
- **Ключ** вводят на лендинге **или** он в **path** ссылки, например `/g/{CODE}` ([протокол v0.1](PROTOCOL.md)); в v0.1 **имя** вводят **на арене** до join по WebSocket.  
- Сервер **связывает** клиента с комнатой по коду (и, при реализации, токену сессии).

## 2. Роли

- **Создатель группы** — тот, кто создал сессию и раздал ключ; по умолчанию считается **ведущим** (facilitator) ретро.
- **Ведущий** — может объявлять **этапы** ретро; управление доступно в UI.
- **Назначение ведущего** — ведущий (или создатель, если иначе не оговорено) может **передать** роль другому участнику.

## 3. Персонажи и боевая механика (арена)

- Каждый игрок **выбирает одного** из доступных персонажей (например: рыцарь, маг, скелет, разведчик).
- У каждого персонажа **одна** активная **способность** (указаны как примеры: маг — «фаерболы», рыцарь — удар мечом, разведчик — лук).
- **Сайд-активности** вне блокировки этапами: игроки могут **перемещаться** по небольшой локации, сражаться с **простыми** врагами (крысы, летучие мыши, скелеты); побег даёт **золото** (косметическое/игровое, деталь баланса — позже).

## 4. Сценарий (контент ретро)

- **Создатель** при создании/настройке сессии **выбирает сценарий** (шуточный).
- Сценарий определяет:
  - **локацию** (визуал и раскладку);
  - **метафору сбора карточек** (стол, кубок, сундук и т.д.);
  - нарратив и формулировки в UI.
- **Финальный этап** сценария — **анонимное голосование**: насколько участники довольны исходом ретро и **выполнением сценария** (см. [SCENARIOS.md](SCENARIOS.md)).

## 5. Этапы ретро (фазы)

Ведущий последовательно объявляет этапы. Ниже — логика; конкретная реализация (анимации «вылета», «увеличения» карточки и т.д.) — в дизайне и итерациях.

1. **Сбор положительных карточек** — участники поочерёдно (или в заданном порядке) «подносят» карточки к объекту сценария (стол, кубок).
2. **Вскрытие положительных** — все карточки показаны команде.
3. **Поочерёдная презентация** — выбранная карточка **выделяется** (крупнее) для обсуждения внешним каналом.
4. **Сбор негативных карточек** — аналогично этапу 1, для негативного столбца.
5. **Вскрытие негативных** — аналогично этапу 2.
6. **Голосование за приоритет** — краткое ранжирование/голосование по карточкам (для фокуса).
7. **Разбор и action items** — фиксация плана действий по итогам.
8. **Финал сценария** — **анонимное голосование** «успех ретро / сценария» (детализация в [SCENARIOS.md](SCENARIOS.md)).

Переходы между этапами инициирует **только ведущий** (кроме случаев, явно оговорённых позже, например тайм-ауты).

## 6. Вне scope

- Встроенный аудио/видео-чат.
- Сохранение персональных данных сверх **отображаемого имени** в сессии (политика — в [NFR.md](NFR.md)).

## 7. Визуал

- Ориентир: **Vampire Survivors** — читаемая 2D, простые формы.
- **Тайлы и персонажи — 32×32 px** (логические пиксели; масштаб на экране — через CSS/канвас).
- Анимации — покадровые в спрайтах **или** простые: сдвиг/подпрыгивание при ходьбе, «рывок» при атаке.
