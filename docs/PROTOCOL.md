# Контракт v0.1

Согласованное поведение **клиент** + **сервер** v0.1. Сводка **продукта** в [MVP.md](MVP.md) (секция MVP v0.1).

## URL и маршрутизация

- **Deep link:** path `/g/{inviteCode}`. **Синоним** (тот же экран): `/join/{inviteCode}`.
- `inviteCode` — строка, которую API возвращает при **создании** комнаты; без query для кода.  
- **Сервер (Go):** `GET /`, `GET /g/*`, `GET /join/*` — один и тот же `index.html` (SPA), клиент читает `location.pathname` и открывает **арену** с Phaser.  
- Лендинг `/` — **без** Phaser; Phaser **только** на path арены (lazy, [ADR 0003](adr/0003-client-rendering-phaser.md)).

## Имя участника

- **Отображаемое имя** — вводится на **арене** (модалка/форма) **до** открытия **WebSocket**.  
- Пока имя не задано — **не** подключать WS; в **лог** join не писать.
- Ограничение: 1–30 символов; пустое и только-пробельное — не принимать.

## Phaser (клиент)

- **Dynamic** `import('phaser')` в коде, который грузится **только** при входе на маршрут арены. См. [ADR 0003](adr/0003-client-rendering-phaser.md).

## HTTP (создание комнаты)

**`POST /api/v1/rooms`** — создать room в памяти; тело запроса пустое (v0.1).

Ответ **201** JSON:

```json
{
  "roomId":     "ulid-or-uuid",
  "inviteCode": "abc123XYZ789",
  "createdAt":  "2024-01-01T12:00:00.000000000Z",
  "paths": {
    "g":    "/g/abc123XYZ789",
    "join": "/join/abc123XYZ789"
  }
}
```

- `inviteCode` — 12-символьная URL-safe строка (9 случайных байт, base64url без padding).
- Ошибки: `500` при внутренней ошибке.

## WebSocket (соединение)

**URL подключения:** `GET /ws/{inviteCode}?name={displayName}` — HTTP Upgrade до WebSocket.

- `inviteCode` — из `location.pathname` на клиенте.
- `name` — URL-encoded displayName, введённое в форму на арене.
- Если комната не найдена — сервер закрывает соединение с кодом **4004** и текстом `"room not found"`.
- Если имя пустое или отсутствует — сервер закрывает с кодом **4400** и текстом `"name required"`.

Клиент не открывает WS до тех пор, пока пользователь не ввёл имя на арене.

## WebSocket — формат сообщений

Все сообщения — текстовые фреймы с JSON. Структура «конверта»:

```json
{ "type": "<тип события>", "payload": { … } }
```

### Server → Client

**`player_joined`** — новый игрок подключился к комнате:

```json
{
  "type": "player_joined",
  "payload": {
    "displayName":   "Иванов",
    "playerCount":   2
  }
}
```

**`player_left`** — игрок отключился (закрыл вкладку / потерял сеть):

```json
{
  "type": "player_left",
  "payload": {
    "displayName":   "Иванов",
    "playerCount":   1
  }
}
```

**`room_state`** — отправляется только что подключившемуся клиенту сразу после успешного join, чтобы инициализировать список участников:

```json
{
  "type": "room_state",
  "payload": {
    "players":      ["Иванов", "Петрова"],
    "playerCount":  2
  }
}
```

**`error`** — прикладная ошибка (не WS close code):

```json
{ "type": "error", "payload": { "message": "описание ошибки" } }
```

### Client → Server

В v0.1 клиент не шлёт сообщений после установки соединения; все параметры — в URL query при апгрейде.

### Разрыв соединения

Когда клиент закрывает вкладку или пропадает сеть:

1. Сервер получает Close-фрейм или таймаут пинга.
2. Сервер удаляет участника из комнаты.
3. Остальным в комнате рассылается `player_left`.

## Heartbeat (опционально)

Сервер шлёт Ping-фрейм каждые **30 секунд**; клиент (браузер) отвечает Pong автоматически. Если Pong не получен в течение **10 секунд** — соединение закрывается как тайм-аут.
