# CJM: основные сценарии

Цель: **почти линейные** пути **без лишних ветвлений** — в реальном продукте добавляются ошибки сети, валидации, выходы; их обрабатываем в **требованиях** и **e2e** отдельно, в CJM не расписываем.

**Термины:** **организатор** — кто создал сессию и (по умолчанию) **ведущий**; **участник** — вошёл по коду. **Сервер** = веб-интерфейс (лендинг/лобби/создание) + API + раздача клиента; см. `docs/ARCHITECTURE.md`. **Сценарий** (шуточный) задаёт **локацию**, **объект** сбора карточек и шаблон **финального** голосования — `docs/GAME_DESIGN.md`.

---

## CJM-1. Организатор создаёт ретро и получает код

1. Пользователь открывает **URL** приложения (тот же хост, что и сервер).
2. Видит **веб-интерфейс** (стартовый экран).
3. Нажимает **«Создать ретро»** (или эквивалент).
4. **Выбирает сценарий** (шуточный): **локация** + **объект** сбора карточек (кубок, сундук и т.д.) + краткое описание/баннер (TBD в UI).
5. Система создаёт **сессию (группу)** на сервере и показывает **код приглашения** (и готовую **ссылку** с кодом).
6. Организатор **передаёт** код/ссылку **участникам** (мессенджер, устно — вне продукта).

*Дальше участники подключаются; организатор остаётся в **лобби** до готовности. По умолчанию **организатор** = **ведущий** (см. CJM-4).*

---

## CJM-2. Участник входит по коду, имя, ожидание в лобби

1. Участник открывает **URL** (тот же) или **ссылку** с **уже подставленным** кодом.
2. Вводит **код** (если не в ссылке) и **имя** (отображаемый ник).
3. Подтверждает вход **«Войти»** / **«К команде»**.
4. Попадает в **лобби** сессии: видит **список** подключившихся, ожидает, пока все готовы (или сигнал от ведущего).

*Минимальные ответвления, не входящие в «основной» CJM, но важны для e2e: неверный код, дубликат имени, переподключение — `docs/REQUIREMENTS.md` + `docs/E2E.md`.*

---

## CJM-3. Старт: персонаж, арена

1. В **лобби** все отмечены «готовы» (кнопка) **или** ведущий нажимает **«Начать»** (один путь в продукте — зафиксировать в реализации, не раздваивать CJM).
2. Каждый **выбирает персонажа** (один на игрока).
3. Система **переходит** на **локацию (арену)** из **сценария**; ведущий **на** якорной позиции (трон, дракон и т.д.), участники **на** спавнах; **этап** ретро — **начальный** (например, сбор плюсов — `docs/GAME_DESIGN.md`).

---

## CJM-4. Ретро на арене (ведущий ведёт этапы, участники играют)

1. **Ведущий** **переключает этапы** (`docs/REQUIREMENTS.md`, `docs/GAME_DESIGN.md`).
2. **Сбор карточек (позитив/негатив):** участник **подходит** к **объекту сбора** (из **сценария**) **→** **действие** (взаимодействие) **→** **окно** ввода **→** **отправить**; **анонимно** до **вскрытия** (см. `docs/REQUIREMENTS.md`).
3. **Вскрытие** / **презентация** / **голосование за приоритет карточек** / **разбор** и **экшен-план** — **визуал** + **синхронизация**; ведущий **ведёт** порядок, где нужно.
4. Параллельно участники **свободно ходят** и **бьют** простых **врагов**; **золото** с врагов **косметическое** (см. дизайн); **не** влияет на **итоговое** голосование сценария.
5. **После** **разбора** и **фиксации** **экшен-айтемов** **ведущий** **включает** **последний** **этап** **сессии:** **анонимное** **итоговое** **голосование** **сценария** (ЗА / ПРОТИВ) — `docs/GAME_DESIGN.md`.

*Одна ветвь, которую стоит заранее согласовать: **«назначить другого ведущего»** — либо отдельный CJM, либо **один** клик без подсценов.*

---

## CJM-5. Завершение

1. **Ведущий** (или **организатор** — по политике) **закрывает** **сессию** **после** **итогового** **голосования;** **опционально** **кнопка** **«Покинуть сессию»**.
2. **Экран** **итогов** (минимум): **агрегат** **финального** **голосования;** **опционально** **«самый** **богатый»;** **остальное** — **TBD** **(MVP).**
3. Участник может **выйти** / **открыть новую** ссылку (новая сессия — CJM-1 снова).

---

## Сводка: зависимость e2e

| ID     | Сценарий |
|--------|----------|
| CJM-1  | Создать сессию, **выбрать сценарий**, **код/ссылка** |
| CJM-2  | Войти по коду, имя, лобби |
| CJM-3  | Готовность → персонажи → арена |
| CJM-4  | Этапы ведущего, карточка **через объект сбора**, **итоговое голосование** сценария |
| CJM-5  | Завершение, **итоги** (в т.ч. фин. голосование, опцион. «самый богатый») |
