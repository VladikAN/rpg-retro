# Роли и навыки (для людей и агентов)

Связь с документами: CJM, E2E, ARCHITECTURE в каталоге `docs/`. Одна личность может совмещать роли. Агенту: укажите роль в задаче или вставьте готовый промпт из раздела в конце.

## Тестировщик (QA)

- Ведёте e2e по E2E.md, опираясь на CJM.md. Сквозной регресс сценариев пользователя — ваша зона.
- Следите, чтобы важные шаги CJM либо были в e2e, либо имели осознанный gap с отметкой в CJM, E2E или REQUIREMENTS.
- Unit- и интеграционные тесты не отменяют e2e для путей, зафиксированных в карте e2e как критичные.
- Когда e2e подключены в CI, падение e2e = блокер для мержа, пока не зелёный прогон или согласованный skip плюс тикет-технический долг.
- Инструмент по умолчанию: Playwright, см. E2E.md.

## Разработчик (клиент, сервер)

- Соответствие ARCHITECTURE. Любое существенное смещение поведения: обновляйте ARCHITECTURE, при необходимости AGENT, CJM, REQUIREMENTS.
- Принципы: SOLID, DRY, KISS, без догм; KISS важен при конфликте с глубиной иерархий.
- Monorepo: apps/client и apps/server, общий контракт (API, типы) документируйте по мере введения.
- Pull request: сопроводите тестами там, где применимо; не ломайте e2e тихо — согласие с QA или ревьюером.

## Ревьюер кода

- Всё, что требуется от разработчика, плюс проверка: тикет (когда ведёте) закрыт вместе с смысловым обновлением документации, если смена затрагивает путь пользователя (REQUIREMENTS, CJM, AGENT, ARCHITECTURE).
- CJM: не буквальный дифф к каждой строчке, а вопрос «смена продукта отражена в doc».
- Мердж: линтеры, и e2e зелёные, если e2e уже в веточном CI, либо оформлено исключение (skip) с тикетом-обязательством.

## Менеджер

- Ритм, приоритизация, риски, тикеты (когда трекер есть; до этого — соглашения с владельцем).
- Синхронизация с владельцем: требования, сдвиги, технические решения (в том числе Go, WebRTC, деплой).
- В код по умолчанию не вмешивается; при смене продукта — добивает обновления CJM и REQUIREMENTS.
- Удалённый агент не всегда может вести тикеты в GitHub/GitLab; в этом случае бэклог в MD и PROCESS до появления доступа.

## Промпты для агентов (копипаст)

| Роль      | Старт промпта |
| --------- | --------------- |
| QA        | Ты в роли тестировщика: e2e по docs/E2E.md и CJM, не понижай сквозное покрытие без согласования. |
| Dev       | Ты в роли разработчика: docs/ARCHITECTURE, apps/client и apps/server, SOLID, DRY, KISS, небольшой дифф. |
| Reviewer  | Ты в роли ревьюера: как разработчик плюс согласованность с тикетом и с MD/CJM, e2e в CI зелёные либо осознанный skip. |
| PM        | Ты в роли менеджера: план, тикеты, общение с владельцем; в код вмешивайся не по умолчанию, фиксируй сдвиги в требованиях. |

Новые и переименованные роли вводите с согласования (тикет или краткое соглашение с владельцем).
